# ESM(지마켓·옥션) 판매취소 자동화

발주서의 `취소준비` + `판매처=지마켓/옥션` 주문을 ESM Plus 발송관리에서 찾아 일괄 판매취소한다.
쿠팡과 달리 **한 번에 여러 건을 체크해 처리**할 수 있어 훨씬 빠르다.

화면: <https://www.esmplus.com/Home/v2/send-processing>
목록은 `post-tx.esmplus.com` **iframe 안**에 있다. 최상위 document에는 테이블이 없다.

## 실행 절차

### 1단계 — 드라이런

```bash
npm run esm:cancel
```

크롬 실행 → 대상 추출 → 목록 수집 → 대조 → 확인 팝업까지 열고 취소한다.

### 2단계 — 보고

대조 결과를 사용자에게 보고한다. 특히 다음 세 숫자가 맞아떨어지는지 확인한다.

- 매칭 건수 = 발주서 취소대상 건수
- 취소 안 할 행 = 목록 전체 − 매칭
- 목록에 없는 대상 = 0

### 3단계 — 전건 처리

```bash
npm run esm:cancel -- --go
```

페이지당 최대 20건 중 대상만 체크해 처리하고, 목록이 갱신되면 1페이지부터 다시 훑는다.
성공한 건만 발주서를 `취소준비` → `취소완료`로 바꾼다.

## 매칭 규칙

ESM 목록에는 **취소하면 안 되는 주문이 섞여 있다.** 잘못 체크하면 멀쩡한 주문이 취소되므로 다음을 모두 만족할 때만 대상으로 삼는다.

| 키 | 발주서 | ESM 목록 |
|---|---|---|
| 마켓 | `marketplace` | 판매아이디 접두 `G`=지마켓 / `A`=옥션 |
| 수령인명 | `recipient_name` | 수령인명 |
| 구매자명 | `marketplace_orderer_name` | 구매자명 |
| 상품명 | `product_name` | 상품명 |
| 수량 | `quantity` | 수량 |

같은 조합이 여러 건이면 발주서에 있는 개수만큼만 소비한다(다건 주문 오취소 방지).

## 안전장치 (하나라도 어긋나면 중단)

1. 주문번호로 행을 식별한 뒤, 수령인명·상품명·수량을 화면에서 **다시** 대조한다
2. 화면에서 실제 체크된 개수가 기대 개수와 같은지 확인한다
3. 확인 팝업의 "정말 N건을 판매취소" 숫자가 체크 수와 같은지 확인한다

## 주의사항

- **취소 사유를 고르는 UI가 없다.** 무조건 "판매자 귀책 사유"로 처리된다.
- 팝업 경고 그대로 **해당 옵션이 품절처리되고 페널티가 부과된다.** 되돌릴 수 없으므로 반드시 승인을 받고 실행한다.
- 주문상태가 `발송처리필요`인 건과 `발송지연`인 건 **모두** 취소 대상이다. 상태로 거르면 오래된 주문이 조용히 누락된다.
- 목록은 페이지당 20건이고 페이지 크기 변경 수단이 없다. 처리한 행은 목록에서 빠지므로 회차마다 1페이지부터 다시 훑는다.

## 구성 파일

| 파일 | 역할 |
|---|---|
| `scripts/esm-cancel-run.mjs` | 전체 파이프라인 러너 (`npm run esm:cancel`) |
| `scripts/_esm-list.mjs` | 발주서에서 취소준비 지마켓·옥션 추출 |
| `scripts/_esm-collect.mjs` | ESM 발송처리 목록 전 페이지 수집 |
| `scripts/_esm-match.mjs` | 5개 키 대조 |
| `scripts/esm-cancel.mjs` | 판매취소 실행 (`--dry`로 확인 팝업까지만) |
| `scripts/esm-cancel-apply.mjs` | 발주서 취소완료 반영 |

쿠팡은 절차가 전혀 다르다 — `coupang-cancel` 스킬을 쓴다.
