# 상품 대량 등록

마지막 업데이트: 2026-08-30

플레이오토 엑셀 일괄등록으로 **쿠팡·스마트스토어·지마켓/옥션** 세 마켓에 상품을 올리는 방법.
실제 처리 내역이 아니라 **처리 방법**만 기록한다.

관련 스킬: `.claude/skills/product-registration/SKILL.md`
옵시디언 사본: `Documents/Obsidian Vault/10-workflows/상품 대량 등록.md`

---

## 한눈에 보는 순서

```
1. 사전 점검     금칙어 · 용량 · 바코드          (스크립트)
2. 엑셀 생성     build-playauto-excel.mjs        (스크립트)
3. QA 통과       qa-smartstore / qa-esm          (스크립트, 필수)
4. 업로드        플레이오토 → 각 마켓 전송        ← 사장님이 직접
5. 결과 분석     반려 원인 분류 → 고쳐서 재시도    (스크립트)
6. 등록 후 정리  캐시 비우기 → 양식 임포트         ← 사장님이 파일 받아옴
```

**4번과 6번만 사람이 한다.** 나머지는 전부 자동이다.

---

## 절대 규칙

| 규칙 | 이유 |
|---|---|
| 소비자상담번호는 항상 `010-6564-4459` | 제조사 번호 쓰면 안 됨 |
| `판매중지` 상품은 절대 안 건드림 | 엑셀에도 넣지 않는다 |
| 원 판매자 상세페이지 이미지 복사 금지 | 저작권·개인정보로 내려간 이력 있음 |
| 상품명은 한글·영문·숫자·공백만 | 특수문자 반려 (소수점만 예외) |
| 커밋·배포는 승인 후에만 | |

## 1. 사전 점검

```bash
node scripts/scan-forbidden.mjs                    # 금칙어 검사
node scripts/fix-forbidden.mjs --apply             # 치환 적용
node scripts/fill-unit-size-koreannet.mjs --apply  # 이름에 용량 없는 상품 채우기
```

금칙어는 `forbidden_words` 테이블. 새로 발견하면 `forbidden-words-seed.mjs`에 추가.
**상품명·상세설명뿐 아니라 고시 24칸도 검사한다** — 고시 칸이 상세페이지에 그대로 노출되기 때문.

## 2. 엑셀 생성

```bash
node scripts/build-playauto-excel.mjs smartstore --chunk 300
node scripts/build-playauto-excel.mjs gmarket_auction --chunk 300
node scripts/build-playauto-excel.mjs coupang --chunk 300
```

결과: `바탕화면/상품등록/플레이오토_<마켓>_<날짜>_1of4.xlsx`

> ⚠️ **재시도할 때는 반드시 `--retry`를 붙인다.**
> ```bash
> node scripts/build-playauto-excel.mjs smartstore --retry "<결과.xlsx>"
> ```
> 안 붙이면 판매자관리코드가 전부 새로 발급되는 사고가 난다. 아래 [[#판매자관리코드 사고]] 참고.

## 3. QA — 절대 건너뛰지 않는다

```bash
node scripts/qa-smartstore.mjs
node scripts/qa-esm.mjs
node scripts/rebuild-qa-check.mjs
```

**"■ 등록을 막는 문제: 없음"** 이 나와야 업로드로 넘어간다.
새 반려 사유가 나오면 그때마다 QA에 검사를 추가한다. 같은 실수가 두 번 나오면 안 된다.

## 4. 업로드 (사장님)

플레이오토에 엑셀을 올리고 각 마켓으로 전송한다.

## 5. 결과 분석

결과 엑셀을 받으면:

```bash
node scripts/analyze-result.mjs "<결과.xlsx>"
```

**결과 파일은 두 종류다. 섞으면 안 된다.**

| 파일 | 판별 | 뜻 |
|---|---|---|
| 엑셀일괄등록 결과 | `결과` 컬럼 | 플레이오토에 상품이 만들어졌나 |
| 쇼핑몰 작업결과 | `작업결과` 컬럼 | 실제 마켓에 전송됐나 |

플레이오토에 만들어져도 마켓 전송은 실패할 수 있다.
그럴 땐 플레이오토에서 지우고 다시 올린다 (`pa-delete-list.mjs`로 삭제 목록 추출).

## 6. 등록 후 정리 — 빠뜨리면 가격수정이 안 나간다

```bash
node scripts/clear-price-inventory.mjs <esm|smartstore|coupang> --apply
```

그다음 각 셀러센터에서 양식을 받아 임포트한다.

| 마켓 | 받는 곳 | 주의 |
|---|---|---|
| 스마트스토어 | 상품관리 → 상품 일괄수정 | 받은 파일 그대로 |
| 지마켓·옥션 | ESM Plus → 상품관리 → 상품목록 | **가격대량수정 양식 아님** |
| 쿠팡 | WING → 상품 조회/수정 → 가격/재고 일괄변경 | P~S열이 빈 파일이 맞다 |

임포트는 캐시만 채우는 게 아니라 **`platform_codes`에 마켓 상품번호를 넣는다.**
이게 없으면 가격수정 엑셀이 안 만들어진다.

임포트는 상품번호 기준 upsert라 옛 행이 남는다 →
**새로 등록한 뒤엔 반드시 캐시를 비우고 다시 임포트한다.**

# 겪은 함정

전부 실제로 반려·사고가 났던 것들이다.

## 판매자관리코드 사고

가장 위험하다. `--retry` 없이 다시 생성하면 **전 상품에 새 코드가 발급되고 DB를 덮어쓴다.**
이미 올라간 상품이 중복 등록되고 DB와 마켓이 어긋난다.

```bash
node scripts/restore-seller-code.mjs smartstore "<결과.xlsx>" --apply
```

`restore-seller-code.mjs`는 **상품명으로 찾는다.** 이름이 같은 상품이 둘이면 한쪽만 고쳐지므로
먼저 이름 중복을 확인한다.

마켓에서 그 묶음을 통째로 지운 상태라면 코드를 지킬 이유가 없으니 전체 재생성이 더 깔끔하다.

## 쿠팡

- **GTIN(바코드)은 상품 1개당 유일해야 한다.** 묶음수량 변형(210ml 30개 / 60개)은 낱개 바코드가
  같아서 두 번째부터 반려된다 → 상품참조번호를 올리고 체크디짓을 다시 계산한 변형 GTIN 사용 (`--altbarcode`).
  이미 쓴 번호는 `claimed-barcodes.mjs` 목록에서 피한다.
- **`옵션바코드` 컬럼이 GTIN으로 전송된다.** 마스터 `바코드`/`표준상품코드`만으로는 반려.
- **`모델번호`/`옵션 모델번호`가 MPN으로 전송된다.** 바코드 없을 때 품목보고번호를 넣지만,
  GTIN만 받는 카테고리가 많아 성공률은 낮다.
- **필수옵션은 전부 채우거나 아예 안 만든다.** 반쪽이면 "필수 추천 옵션을 모두 선택해주세요"로 반려.
- **단위 표기가 항목마다 다르다.**
  ```
  개당 수량   → 개입 · 롤 · 매 · 세트   ("개" 거부)
  수량/총수량 → 개 · 박스 · 세트         ("개입" 거부)
  총 수량     → 개입                     (에너지/비타민음료 · 녹차티백 · 커피믹스만)
  ```
- **모델명에 특수문자(• · -)가 있으면 반려.**
- 플레이오토가 우리 카테고리를 자기 기준으로 다시 매핑한다.
  `lib/coupang-category-options.ts`는 참고일 뿐 **업로드 결과가 유일한 근거다.**

## 스마트스토어

- **표시 용량은 1~999만 받는다.** 단위가격을 안 쓸 때 `0`을 넣으면 반려 → **빈칸**으로 둔다.
  (이것 때문에 124건이 한 번에 반려된 적 있음)
- 표시 여부가 Y면 구성 방식 · 팩 수량 · 팩당 수량 · 개당 용량이 전부 있어야 한다.
- **고시의 "유전자변형식품", "수입신고 필함 문구"는 Y/N만.** "해당없음"은 반려.
- **카테고리코드는 `smartstore_category_codes`에 실제로 있는 코드만.**
  상위·유사 카테고리로 보내면 쿠팡 필수옵션까지 달라져 연쇄 반려된다.
  (콜라 6373132 · 사이다 6373129 · 캔커피 6373110 등 세부 카테고리 필수)
- 품목고시 코드: `17` 주방용품 / `18` 화장품 / `20` 농수축산물 / `21` 가공식품 /
  `22` 건강기능식품 / `35` 기타재화. 생활화학제품은 공개 자료가 없어 플레이오토 화면에서 확인.

## 지마켓·옥션

- 한 상품에 **옥션·지마켓 두 줄**이 필요하다. 쇼핑몰과 템플릿코드가 짝이어야 한다.
  ```
  옥션=redgoom00   → 2201548
  지마켓=redgoom00 → 2201554
  ```
- 금칙어를 상세설명에서도 막는다. 실제로 "알레르기"로 반려됐다.

## 공통

- **플레이오토 S3 썸네일(`s3-ap-northeast-2.../gmp01/`)은 만료되어 403이 난다.** 업로드 전 HEAD 확인.
- **같은 판매자관리코드로 재업로드하면 "이미 존재"로 막힌다.** 플레이오토에서 지운 뒤 올린다.
- 상세설명은 엑셀 셀 한계 32,767자.

# 바코드 찾는 순서

```
1. 코리안넷 (scripts/output/koreannet-catalog.json, 33,072건)  ← 이름에 용량이 있어 가장 정확
2. 식약처 C005 바코드연계 (258,080건)                          ← 용량 정보 없어 다용량 제품은 모호
3. scripts/barcode-todo.mjs → 바코드_채울목록.xlsx              ← 실물 보고 채움
```

매칭은 **틀리느니 비우는 쪽**으로 짠다. 확인된 실패 사례:

- 괄호 없는 단일 표기를 낱개로 읽으면 안 된다.
  `삼양 큰컵 불닭볶음탕면 1920g`은 16개들이 박스다 → `(120g x 5개입)` 꼴 괄호 표기만 신뢰.
- 이름이 비슷한 다른 맛·다른 제품에 붙는다 (핫식스 포스↔제로, 웰치스 포도↔애플망고, 동원 꽁치↔리챔).
  → 우리 낱말이 후보에 전부 있어야 하고, 후보에만 있는 변형 낱말(제로·무가당·디카페인 등)이 있으면 버린다.

# 등록 이후: 가격수정이 안 나가는 상품 판별

> 2026-08-25에 확인한 내용. 자동 가격갱신 로그에 뜨는
> **"N개 상품은 양식 행이 없어 제외됨"** 의 진짜 의미다.

## 로그의 의미

가격수정 엑셀은 **셀러센터 양식 원본을 DB에 캐시해두고 거기에 새 가격만 덮어쓰는** 방식이다.
그래서 **DB에 그 상품 줄이 없으면 새 가격을 적을 곳이 없어 통째로 건너뛴다.**

## 원인은 두 가지뿐이다

| 원인 | 판별 | 조치 |
|---|---|---|
| ① 마켓에 **등록 자체가 안 된** 상품 | 셀러센터 상품 수 < 우리 DB 상품 수 | 마켓에 실제로 등록해야 함. **양식 재임포트로는 해결 안 됨** |
| ② `판매중지` 상품 | `registration_status` | 정상. 조치 불필요 |

**양식이 낡아서가 아니다.** 새 양식을 받아 넣어도 숫자는 그대로다 — 실제로 확인했다.

## 2026-08-25 실측

| 마켓 | 양식에 없는 상품 | 그중 판매중 | 판매중지(정상) |
|---|---|---|---|
| 쿠팡 | 249개 | **226개** | 23개 |
| 스마트스토어 | 107개 | **73개** | 34개 |
| 옥션·지마켓 | 34개 | 3개 | 31개 |

쿠팡 셀러센터 상품 922종(옵션 포함 1,012행) vs 우리 DB 1,170개 → **약 250개가 쿠팡 미등록**.

## 임포트 매칭 방식 (중요)

**쿠팡 `H열 = 업체 등록 상품명`과 우리 `product_name`의 완전일치**로 붙는다.
(공백 정리와 유니코드 정규화만 하고, 그 외 보정 없음)

- 글자 하나만 달라도 안 붙는다. 실제 사례: 우리 `…제로칼로리 콜라` vs 쿠팡 `…제로칼로리 다이어트 콜라`
- 임포트 모달의 **"미매칭 상품"** 은 *쿠팡에 있는데 우리 DB에 없는* 것 (반대 방향)
- 우리 DB에만 있는 상품은 모달에 안 뜬다 → 위 표처럼 따로 조회해야 보인다

## 점검 방법

```
쿠팡 셀러센터 "상품 조회/수정" 화면의 전체 개수  vs  우리 DB 상품 수
```

두 숫자 차이가 곧 미등록 상품 수다. 차이가 크면 재등록 대상을 뽑는다.
